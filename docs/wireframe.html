Decisions I need from you

The router becomes a rule engineToday it has three fixed branches. The builder above needs `Autopilot { rules: Vec<Rule> }` with `Rule { conditions, match_all, action, cooldown_ledgers }` and enums for the condition and action kinds, keyed by `(user, autopilot_id)`, plus `last_fired` per rule for the cooldown. `tick(user, id)` walks the list. Any is as cheap as all on-chain, so both are in. This is the first thing I build, about two to three hours including keeper changes and re-running the three live scenarios. Say yes and I start with it.
Withdraw and send to TRY as an agent actionThe policy only lets the agent send USDC to the XOXNO pool, and a landing account is created per withdrawal, so the agent cannot pay it. Two options: the rule withdraws to the wallet and the Funds page shows a "ready to cash out" banner the user confirms with one passkey, or the router owns a fixed exit escrow the policy allows and the keeper cashes out from there. I recommend the first for the hackathon. It is honest and the demo shows the passkey once.
Sentence to ruleA server route that calls Claude with the condition and action vocabulary as a JSON schema, returns chips, never saves the sentence. If you would rather not depend on an API key in the demo, I keep the input but hide it behind an env flag.
NFT cardShown only if the XOXNO testnet controller has a position NFT contract deployed. I check first and skip the card if not.
